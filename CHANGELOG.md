# История изменений

Версии программы NAPI Board Config. Номер версии EEPROM указан отдельно;
номер программы не означает изменение бинарного формата.

## v22 — штатные EEPROM-оверлеи AT24

- Поддержаны штатные EEPROM-оверлеи `napi-rk3308-i2c1-at24.dtbo` (Armbian)
  и `rk3308-i2c1-at24.dtbo` (NapiLinux/Yocto).
- При недоступной EEPROM сервисный пункт автоматически предлагает найденный
  штатный `i2c1-at24`, затем требует просмотр и `yes` перед записью/reboot.
- Включение выполняется через `overlays=` в boot-файле; `user_overlays` сохраняется.
  Включённый at24 сохраняется при последующем формировании строки с выбранной I2C1.
- Сообщение об отсутствии оверлея указывает ожидаемый штатный файл.
  Поиск старых стандартных EEPROM-оверлеев сохранён для совместимости.

## v21 — просмотр EEPROM и независимый I2C1

- Добавлен `View EEPROM` перед `Load EEPROM`: просмотр фактических полей,
  MAC, processor ID и проверки CRC без изменения текущих настроек меню.
- Для пустой или повреждённой EEPROM показываются причина и сырые байты.
- При совпадении processor ID с OTP убрана штатная пометка `in EEPROM`.
  Сообщения об отсутствии привязки, несовпадении и недоступном OTP сохранены.
- I2C1 добавляется в строку overlays отдельно от RTC:
  `overlays=i2c1 i2c1-ds1338`. Автоматическое определение префикса сохранено.
- Формат EEPROM остаётся v3; v2 по-прежнему читается.
- Проверено: 87 тестов локально и на NAPI-C, TUI 120×40 и 60×24.
  Проверки на реальной плате не изменяли EEPROM и boot-файл.

## v20 — EEPROM Format v3 и привязка процессора

- Введён EEPROM Format v3: processor ID отделён от серийного номера платы,
  CRC перенесена в `0x7A`, размер используемой области — 126 байт.
- Чтение v2 сохранено; миграция в v3 выполняется отдельной CLI-командой
  с подтверждением, резервной копией и проверкой чтением.
- Добавлены состояния привязки: NOT BOUND, MATCH, PROCESSOR MISMATCH,
  OTP UNAVAILABLE. Существующая привязка не заменяется молча.
- Полная `Write EEPROM` предлагает текущий OTP, если привязка ещё не задана.
- Добавлены `Reset EEPROM` и `Reset processor ID`. Первый обнуляет все
  256 байт, сохраняя настройки меню; второй очищает только привязку и
  пересчитывает CRC, сохраняя остальные данные EEPROM.
- ACTIONS и SERVICE размещены рядом в широком терминале; навигация циклическая.
- MAC объединены в `View and generate MACs`, boot-файл — в
  `View and write boot config` с полным сравнением новых и текущих строк.
- I2C1 остаётся независимым параметром конфигурации EEPROM.

**Совместимость:** v19 не читает EEPROM v3. Возврат к старой программе сам
по себе не восстанавливает прежний формат EEPROM.

## v19 — стабильные MAC из RK3308 OTP

- Генерация восьми локальных unicast MAC из пяти байт RK3308 OTP
  (offset 20) по SHA-256 с namespace `NAPI-MAC-v1`.
- Чтение NVMEM с блокировкой и проверкой ID; без fallback на serial,
  случайность, время или текущие MAC интерфейсов.
- Зафиксированы назначения восьми MAC-слотов и настройка
  `set_native_eth_mac: false` по умолчанию.
- После генерации предлагается отдельная запись только MAC, mac_count и CRC.
- Полная запись показывает все параметры EEPROM. В широком терминале
  новые значения показаны слева, текущие справа; в узком — последовательно.

## v18 — настройка поддержки EEPROM

- Добавлен выбор стандартного EEPROM overlay с подтверждением модели,
  шины и адреса перед изменением boot-конфигурации и перезагрузкой.
- Учитывается доступность EEPROM через основной Device Tree.
- При отсутствии стандартного overlay предлагается ручная настройка
  `user_overlays`; пользовательские файлы не изменяются автоматически.

## v17 — автоматическая boot-конфигурация

- Автоматический выбор `armbianEnv.txt`/`uEnv.txt` и чтение `overlay_prefix`.
- Предварительный просмотр строки overlays и подтверждение записи.
- Предупреждения отделены от предлагаемого содержимого файла.
- Сохраняются `user_overlays` и ранее включённый EEPROM overlay при
  выбранной I2C1; пользовательские overlays не сопоставляются по именам.
- Корректная EEPROM загружается при запуске TUI; недоступные действия
  помечаются `disabled` с причиной.
- README переведён на русский: назначение, зависимости и команды.

## v16 — разделение архитектуры

- Выделены общий Core, аппаратные адаптеры Linux, TUI и CLI.
- Добавлены команды для EEPROM, MAC, платы и overlays.
- Бизнес-логика и доступ к аппаратуре вынесены из пользовательских интерфейсов.

## v15 — MAC и подтверждения

- Добавлены просмотр и генерация MAC в меню.
- Загрузка профиля из локальной базы выполняется с подтверждением.

История до v15 сохранена в Git как исходное состояние проекта.
